# Smart POS — Architecture & Development Documentation

## 1. Architecture Overview

Smart POS is an offline-first Windows Desktop retail Point of Sale & Commercial Management System built with:

- **Desktop Runtime**: Electron 45 (`main` / `preload` / `renderer` strictly separated)
- **Frontend**: React 19 + TypeScript + Tailwind CSS v4 + Zustand + Recharts + Lucide Icons
- **Typography**: Bundled offline fonts (`@fontsource-variable/inter` for French/Latin, `@fontsource/cairo` for Arabic RTL)
- **Database**: SQLite 3.53 via `better-sqlite3` (`journal_mode = WAL`, `synchronous = FULL`, `foreign_keys = ON`)
- **Validation & Precision**: `zod` schemas at IPC boundaries + `decimal.js` for decimal-safe centime and milli-unit calculations
- **Barcodes & Printing**: `bwip-js` (EAN-13 & Code 128 PNG/HTML/PDF rendering) + ESC/POS raw TCP/Serial & Windows printer driver support
- **Hardware Serial Communication**: `serialport` with modular protocol adapters (`Simulated`, `Generic ASCII`, `CAS`, `Mettler-Toledo SICS`)

### Process Security Rules
- `contextIsolation: true`
- `nodeIntegration: false`
- Typed IPC bridge exposed exclusively via `contextBridge.exposeInMainWorld('api', api)` in `src/preload/index.ts`.
- Persistent database stored in `%APPDATA%\smart-pos\data\smartpos.sqlite` (never inside the program installation folder), ensuring data survives application updates and reinstallations.

## 2. Database Schema & Monetary/Quantity Precision

- **Monetary values**: Stored as integer **centimes** (`1 DH = 100 centimes`).
- **Quantities**: Stored as integer **milli-units** (`1 kg = 1000 milli-kg`, `1 L = 1000 milli-L`, `1 pc = 1000 milli-pc`).
- **Atomic Transactions**: All multi-table writes (`createSale`, `createSaleReturn`, `recordCustomerPayment`, `createPurchase`, `receivePurchase`, `createPurchaseReturn`, `finalizeInventoryCount`) execute inside `db.transaction(...).immediate()`. Any validation or stock error rolls back the entire operation.
- **Single Choke Point for Stock**: `applyStockMovement()` in `src/main/services/stock.ts` is the only function that updates `products.stock_milli` and `products.avg_cost_cents`, recording a traceable row in `stock_movements` (`PURCHASE`, `SALE`, `SALE_RETURN`, `PURCHASE_RETURN`, `ADJUSTMENT`, `INITIAL_STOCK`, `DAMAGE`, `EXPIRATION`, `INVENTORY`).
- **Historical COGS**: Every `sale_items` row snapshots `unit_cost_cents` and `cost_cents` at the moment of sale so historical gross profit and net profit reports remain accurate even after purchase prices change.

## 3. Adding a New Electronic Scale Protocol Adapter

Electronic scales vary by manufacturer. To add a new model:
1. Open `src/main/services/scale.ts`.
2. Create an object implementing `ScaleProtocolAdapter`:
   ```ts
   export const MyCustomScaleAdapter: ScaleProtocolAdapter = {
     id: 'my_scale',
     name: 'My Scale Model',
     defaultPollCommand: 'W\r\n',
     parseFrame(rawFrame, defaultUnit) {
       // Parse rawFrame and return { weightGrams, stable } or null
     }
   }
   ```
3. Register it in `SCALE_ADAPTERS` (`src/main/services/scale.ts`) and add the adapter ID to `scaleSettingsSchema` in `src/shared/settings.ts`.

## 4. Known Hardware & Environment Limitations

1. **Physical Thermal Printer / Label Printer**: When no physical printer is attached to the Windows machine, Smart POS provides full HTML preview and one-click **PDF Export** (`58 mm`, `80 mm`, or custom label dimensions) in addition to Windows driver and ESC/POS TCP/Serial modes.
2. **Physical Electronic Scale**: When no RS-232 / USB-Serial scale is connected, the **Simulated Scale Adapter** is clearly labeled with a `SIMULÉE` / `محاكاة` badge and includes an interactive weight slider (`10 g – 5000 g`) for testing and training.
3. **Internal Barcodes**: Internal store barcodes generated by Smart POS use the GS1 restricted-circulation prefix range `20–29` (default `21`) for EAN-13 or `SP` prefix for Code 128, and are explicitly labeled as internal store codes (never impersonating official GS1 manufacturer prefixes).
